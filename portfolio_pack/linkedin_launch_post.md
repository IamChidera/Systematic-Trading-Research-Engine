# LinkedIn Launch Post

I recently built a Python project that I am proud of: a Systematic Trading Research Engine.

The goal was not just to backtest one strategy and show a nice return curve. I wanted to build a more complete research and operations workflow around systematic trading ideas.

The project includes:

- multi-asset strategy backtesting
- regime and momentum filters
- portfolio allocation testing
- walk-forward validation
- fee and slippage stress testing
- SQLite paper-state persistence
- execution-cost dry-runs
- risk snapshots
- daily operations journals
- signal proximity monitoring
- a Streamlit operations dashboard

One of the most useful lessons from the project was that trading research is not only about finding signals. A system also needs execution assumptions, state recovery, risk controls, monitoring, and clear evidence that quiet periods are healthy waiting rather than silent failure.

This project helped me connect Python engineering, data analysis, time-series modelling, and operational thinking in one practical system.
